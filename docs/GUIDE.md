# EDSMT user guide

Every key, window and setting, in the order you meet them on a run. The
front page of the repository is [README.md](../README.md); what changed in
each version is in [CHANGELOG.md](../CHANGELOG.md).

## Using EDSMT

The keys are **Left Alt and the number row, in the order you work a
signal** — step 3 is Alt+3. The number row, not the number pad.

1. **Jump in and honk.** Fire the discovery scanner so every body shows.
2. **Click Where to land.** It ranks the system's bodies for the Rhino —
   pick one and fly to it. A body at or over 2 g gets a big warning.
3. **Map the body with the DSS.** It reports *Planetary Mining Locations*,
   numbered, scattered across the surface.
4. **Target the one you want, glide down and land by it.** When the game
   names the number, EDSMT picks the same signal for you.
5. **Deploy the Rhino** — out of glide and under 30 m. The guide waits for
   both before it says so.
6. **Drive to the middle and press Alt+1.** That logs the signal and sets
   the centre of the survey area. No commodities needed — they come with the
   deposits. The number is picked for you: the one the game has targeted,
   the one in the box if it is free, the one you are standing in, or the
   next free number, so a new signal never lands on an old one.
7. **Hold the mineral scanner down and keep holding it.** Drive out to the
   location's edge line and press **Alt+2** there — that is the border — then
   keep it held while you map the area. The scope keeps you in the picture
   the whole way out, and shades what you have swept inside the border.
8. **Drive to a deposit, fill in the boxes, press Alt+3.** Commodity, rigs,
   Amount, Density — pick with the mouse or type, and Tab moves on. All four
   are needed: a deposit is not marked with any of them blank (the scanner's
   density counts when the game names one), and the rigs, amount and density
   boxes clear themselves for the next one. Rigs is how many the site takes,
   1 to 12 — a Rhino carries six, and a good deposit takes two Rhinos' worth.
9. **Alt+4 to Alt+9 as each rig goes down** — rig 1 is Alt+4, rig 6 is
   Alt+9. Each rig is drawn on the scope and the compass in the colour of
   what it is mining, with its name beside it. Drive too far from one and the
   overlay says so. The first rig down starts your earnings session.
10. **The same number with AltGr picks that rig up** — AltGr+4 is rig 1 up.
    The last one up ends the session. **AltGr+0** is every rig up at once,
    and **AltGr+3** updates the deposit you are standing on.

| Key | Does |
|---|---|
| Alt+1 | Log the signal and set the centre |
| Alt+2 | Survey border here |
| Alt+3 | Mark the deposit |
| Alt+4 to Alt+9 | Rig 1 to rig 6 down |
| AltGr+4 to AltGr+9 | Rig 1 to rig 6 up |
| AltGr+3 | Update the deposit I am on |
| AltGr+0 | Every rig up |
| AltGr+2 | Rig planner: trace the deposit's edge |
| Alt+0 | Overlay on / off |

The overlay only comes up while you are driving a Rhino - not in the ship,
on foot or in the Nomad. Settings > Overlay can show it everywhere.

**AltGr** is what UK and European keyboards call the right-hand Alt key.
Windows sees it as Ctrl+Alt, so on a keyboard without one — a US layout —
the same keys are **Ctrl+Alt+4** and so on, and EDSMT names them that way.
None of these keys is bound by any of the game's own control schemes.

Every one can be changed in **Settings → Keys** — click it and press the
key you want, with or without Ctrl, Alt or Shift — and **Reset** puts it
back. Windows hands out a key like this without telling the two Alt keys
apart, so either Alt works. The game's own number-row keys (the panels, on
most layouts) are plain 1 to 4, without Alt; if your layout puts something on
Alt and a number, or another program of yours does, move one of the two.

**Keys other programs own.** Whoever registers a key first gets it, and
EDSMT never hears it. Settings names the program that has it the moment you press one of
these: graphics-driver capture keys (Alt+F1, Alt+F3, Alt+F9, Alt+Shift+F10,
Alt+Z, Alt+R and Ctrl+Shift combinations); any Win+ key (Windows and the Xbox
Game Bar); the Shift+Tab and F12 keys of game-launcher overlays; the Shift+\`
and Ctrl+Shift+M/D keys of chat overlays; and the game's F10 and Alt+F10. You
can still keep one if that program is off on your machine.

**The guide.** A GUIDE box over the game shows the step you are on, the key
for it, and what comes next, and moves on by itself as each step is done. It
is on for a first run and switches itself off once you have followed it all
the way through; Settings → Basics turns it back on.

**Not sure what something does? Rest the mouse on it.** Every control in
every window says what it does. The first start also walks you round the
main window once — Back, Next, Skip — and never over the game. Its card
stays inside the EDSMT window, beside what it is talking about and clear of
the buttons it names, and it rings each control without moving anything. It
covers the status strip, the map and its key, the tabs, the shortcut bar,
Settings and Help. Settings → Basics turns the notes off, and **Show me round
again** (or **Help → Show me round**) runs the tour.

**The welcome window** opens on the first start of each new version: what
EDSMT is, **CHECK THE SETTINGS** with an **Open Settings** button, the
headlines of what is new in this version with the full patch notes a click
away, **Join the Discord**, radioraxxla.com and **Sign in to the site** (a
member page for any commander, in the squadron or not), a picture of how it
works, **How to customise the map** (what the marks are and where the
switches are, with a **Map key and switches** button), the community map, a
**Donate with PayPal** button for Radio Raxxla, an **HCS Voice Packs** button
(an affiliate link: Radio Raxxla earns a commission at no extra cost to
you; it is also the last entry under **Help**),
and the user guide, bug reports, the changelog and the tour. Tick *Don't show this again* and it stays shut until
the next version. **Help** on the top bar, and **Welcome again** in Settings
→ About, open it whenever you want.

**The main window**, from the top: the top bar (where you are, the run's
worth, Overlay, Settings and Help); the **status strip** — CMDR, ship,
system, body, whether you are docked, landed, in the SRV, on foot or in
flight, and whether the overlay is up, all as the journal says them; the
**tabs**; the rail and the map, with four figures over the map — the
session's tonnes, Cr/hr, the rigs down and how much of the survey area is
swept; the status line; and along the bottom the keys, **SPACING**
(*Comfortable* or *Compact* — how much room the bars and tables leave, at
once) and the **THEME** with **<** and **>** to step through every theme.

**Settings is in tabs** — Basics, Theme, Overlay, Keys, Rigs, Sharing, Your data,
About. Each tab scrolls on its own, and Save and Close are under all of them.

**Find, My sites, Where to land, Earnings, Powerplay and Leaderboard open as
tabs** of the main window, in the strip under the status strip with **Map**
to come back — or **F2** to **F8** from the keyboard, F2 being the map. The
one on show is lit, and it has the window's whole width. **Pop out**, at the
right of any tab's header, moves that one tool out to a window of its own as
it stands, and **Dock** on that window brings it back. To have them all open
as windows, the first switch on Settings → Basics, *Open Find, Earnings and
the other tools as tabs*, turns tabs off.

**There is no centre to set and no bearing to work out.** A deposit records
where it is, and distances and directions are worked out live from wherever
you are standing, so nothing has to be pressed before a find can be recorded.

**Every box, every time.** A deposit goes on the map with its commodity,
rigs, amount and density, or not at all, so every shared find is complete.
Anything that changes later, **UPDATE** puts right.

**Amount and Density are different things.** Density is how rich the deposit
is — Low, Medium, High — and does not change. Amount is how much is left, and
walks down to Depleted as you work it. A site can be High density and
Depleted at the same time: rich, empty today, worth coming back to.

**UPDATE** sits beside MARK DEPOSIT. Standing on a deposit you have already
marked, it writes what the boxes say — the Amount going down as you work
it, a rig count you now know — onto that deposit instead of adding a second
copy. A blank box changes nothing, and the note is stamped with when. The
copy on the community map is updated too. MARK asks first if you already
have that commodity marked within 100 m — press MARK again within a few
seconds to add it as a separate deposit anyway. And if a **different**
commodity is already marked on the spot you are standing on — the box said
Monazite, it was Alexandrite — MARK asks too: **AltGr+3** renames the one
there, keeping its position, history and tonnes, and **Alt+3** again adds
the new one as a deposit of its own.

**Filed under the wrong number?** A find within 5 km of the signal you are
on, filed under another number, is listed under it with a **file under**
button that puts the number right.

**Deposit depleted** (one deposit) sets it to Depleted and stamps the note
with the date and time — `Mined 10/09/2026 01:05`. Press it again next month
and it adds another line, so the site keeps its history. It is not a delete:
the deposit stays on the map, labelled **DEPLETED** with the day it was first
marked (`Periclase dunite  5.53 km  3R  DEPLETED 21 Nov`), until somebody says
it is back.

**The commodity box filters as you type** and is sorted roughly by worth.
Typing `bastna` finds Bastnäsite without the umlaut. The ordering is what the
surface-mining tables say a commodity averages, with a coarse band standing in
for anything outside them — a rough guide, not a quote. Live community
prices override it where they are available.

**Best patch** finds the tightest group with the most rigs and the most
different commodities in it, and points the map at it — the surface
equivalent of overlapping hotspots.

**Location depleted** (the whole signal) tells everyone the location is
stripped, so nobody drives out to it. It is not a delete: the location drops
out of search results and climbs back as it regenerates. Your own deposits
in it stay on your map as they are.

**Got one wrong?** Every deposit in the selected signal is listed in the
left panel with an **edit** button beside it, and you can still double-click
it on the map. Signal number, commodity,
rigs, density and notes are all editable, and Delete is in the same window
behind a second press.

**Signals can be corrected too.** Every row in the mining locations list has
an **edit** button: change the number, change what it offers, or remove it.
Renumbering a signal takes its deposits with it, so none are left under a
number that no longer exists. Deleting a signal does *not* delete its
deposits: they stay on the map, and the window tells you how many before you
commit.

**Export CSV**, in the same window, saves everything EDSMT knows about that
signal in one file a spreadsheet or a map tool opens: where it was logged
and what it offers, the survey centre and border (the border as its radius
in metres), every deposit with its density, amount, rigs and who found it,
each traced deposit edge with its rig pins, and the line the Rhino drove.
One row per thing; the first column, `kind`, says which (`export`,
`signal`, `centre`, `border`, `deposit`, `trace`, `pin`, `drive`), and
`group` ties a trace to its pins. The first row says the EDSMT version and
the file's format number.

The position and the timestamp are shown but not editable. If a deposit
really is in the wrong place, delete it and mark it again. A correction goes
to the community map too: the amount, density and rig count there are put
right.

The map works with Elite closed. It falls back to the last body you recorded
on and centres on the finds themselves.

**Drag the map** to move around it, scroll to zoom, right-click for
**Recentre** (back to you in the middle), the map's key and its switches.

**Back up your finds** from Settings — one dated zip with everything in it.
Restore puts it back and keeps whatever was already there alongside, renamed
rather than overwritten.

## Earnings, and where to sell

**Earnings** is your Rhino mining and nothing else. A session starts with
your **first rig down**, or the first tonne the Rhino refines if you do not
use the rig keys, or **Start session**. It ends when **every rig is back
up**, when the Rhino comes back aboard, or on **End session**. The Rhino
going out on its own is not a session — it goes out to look and to fetch
cargo too. Rigs going down again on the same body within ten minutes carry
the same session on. Every tonne it refines is counted, every transfer to
the ship is counted, and when you sell what it dug up the credits go against
the session that dug it — trading, hauling, exploration and asteroid mining
never appear. Restarting EDSMT in the middle of one does not count anything
twice.

The window is four pages, and each shows only its own: **This session** —
the session you are on as cards (time, tonnes, t/hr, estimated value,
Cr/hr, merits earned and merits an hour), the hold line, and Start, Pause,
End and Multi-session; **Where to sell** — what is aboard and where it
sells best; **Sessions** — every session, with the all-time totals under
the table; and **System prices** — the last known prices in a system you
name. The page you leave it on is the one it opens on next time.

**The big tables** — Sessions, Find, My sites and Where to land — hold every
row at once, however many there are, and scroll straight through them. Click
a row to pick it: its buttons (copy, card, delete, the marks) are on the line
under the table. Ctrl or Shift picks several, **Ctrl+C** copies them, a
double-click does the first thing on the line and a right-click lists them
all. Click a heading to sort; click it again to turn it round. A row is
coloured by its cells — green for good, amber for caution — and a short cell
such as **Why** shows its whole sentence when the mouse rests on it.

**Rhinos in the totals.** Under the all-time line, with more than one Rhino in
your sessions, Earnings gives each Rhino's tonnes. With the wing link on it
adds a **Wing** line: your own Rhinos' total, said to be yours, because the
wing link does not carry tonnes or credits, so wingmates' are not added in.

**Export CSV.** Sessions and Find each have an **Export CSV** button beside
Copy all. It saves what is on screen, in the order it is sorted, as a CSV file
in UTF-8 with a byte-order mark, so Excel opens it with the accents and dashes
right.

**What the game itself says about a session.** The Sessions table checks a
session against the game's own records where the journal has them:

- **To ship** is what the Rhino moved across to the ship. Once the Rhino is
  back aboard the game states the ship's whole hold, and the cell says
  **hold agrees** when it rose by exactly what was moved across (**hold
  differs** when something else came aboard or went). A session's tonnes,
  and its t/hr, are what went across; the tonnes refined stay the live count
  while the Rhino is out, because the game writes one for each tonne.
- **Thrown out** under Mined is cargo of the session's own ore you threw out
  of the hold while it was open.
- **Sold at** gives, after the station's name, how the price there had moved
  by the next time you opened that market (**next read -36%**). The whole
  line, on the cell's note and in Copy, has the price before the sale, the
  price you sold at, and the next one with its date.
- At each login the game writes its own mining figures. From the second
  login on, the line under the table puts what the game counted between
  your last two logins beside the sessions EDSMT has for that time. The game
  counts all mining — a ring as well as a Rhino — so a difference is not a
  fault, and the line says which it is.

While a session is running, **This session** also says what is in the Rhino
now, from the count the game writes with every tonne.

**Delete** on a row takes a session out — a test run, one opened by mistake.
Press it twice on the same row; the file before is kept as
`sessions.csv.bak`.

**Pause** stops the clock — a break, the drive to a station — and credits
per hour leaves paused time out. A rig down, a tonne refined or the Rhino
going out starts it again by itself. **Multi-session** keeps one session
going across trips — fill the ship, fly to a station, sell, come back, go
again — until you untick it.

**More than one SRV on the ship.** A crewmate taking the ship's other Rhino
out is not your trip, and it coming back aboard does not end your session:
EDSMT follows your own SRV.

After every transfer to the ship the overlay flashes what is in the ship and
the room left, and the STATUS box shows the ship's and the Rhino's holds for
the whole session.

The hold line names the **SRV** and the **ship** separately, and counts
only what a Rhino session dug up and has not sold — cargo you bought or
hauled is left out. It gives an estimate at the **galactic average**: the
game's own figure, read off any commodity market you open, or EDSMT's table
until you have (marked *). **Where to sell what is aboard** asks, for each
commodity mined, where it sells best within the distance you choose **of the
system you are in**, and shows three prices side by side: the galactic
average, the best in **this system**, and the **best within** the distance —
so you can see that the station two jumps away pays more before you fly
there. The strip in the main window quotes the total too.

**System prices** looks up any system you name — or the one you are in,
if you leave it blank — and lists the **last known sell price** of each
commodity at every market there: the station, its type and largest pad, the
demand, **when** the price was last seen and **whose** reading it is — another
commander's market read or the market index, whichever is newer. Tick the
commodities you want (as many as you like) or leave it on **Any** for all
thirteen. **Best market only** shows the best station for each commodity
with how many markets there buy it; untick it to see every one. The answer
opens the **System prices** page; **Copy all** on each page copies that
page's table.

**Tonnes mined per deposit.** Every tonne refined is counted against the
marked deposit it came from, and the selected deposit shows what it has given,
by-products and all. Once you have worked a deposit out it says what it holds;
before that, **est. holds** and **est. left** come from the deposits you have
worked out with the same rigs and density, and say how many they rest on.

**One stop for the whole hold.** Under the prices, Where to sell names the
three stations that pay the most for everything aboard - ship and SRV
together - with what each takes of every commodity, where its demand runs
out, what it does not buy, how old its prices are and how many jumps away it
is. The distance box takes light years or 1, 2, 4 or 8 jumps, at your ship's
jump range (or the one in Settings → Basics). When a station has been read
twice, its line says which way the price and demand moved, and over how long.

## Themes

Settings has a **Theme** tab, second from the left, with a picker for the app
and one for the overlay and a strip of each theme's colours under them.
Fourteen themes, all on a dark ground: the Radio Raxxla cockpit, Elite orange,
Signal teal, Ice blue, Green phosphor, Amber terminal, Crimson alert, Deep
space violet, Imperial gold, Fleet blue, Xeno green, Nebula pink, High
contrast, and a colour-safe blue and orange. Then twelve **Powerplay** themes,
one in each Power's colours - pick a Power and both the app and the overlay
take it. Every one is held to readable contrast. The overlay changes the
moment you Save; the app wears a new theme from the next start, and **Save
and restart now** does that straight away.

**Overlay uses the app theme** is on for a new install: the overlay wears
whatever the app wears, its own picker is greyed out, and a new app theme
reaches the overlay as soon as it is saved. Switch it off to give the
overlay a theme of its own. (A settings file from before the switch keeps
the overlay it had: on only where the two themes were already the same.)
The **<** and **>** beside **THEME** at the bottom of the main window step
through every theme the same way, kept at once.

**Match my in-game HUD colours** reads the colours your game is actually
using - the HUD colour matrix in `GraphicsConfigurationOverride.xml`, or
EDHM's main text colour when that mod is installed - and makes a theme of
them for the app and the overlay together. It says what it found: the file
it read, or that the game is on its standard orange. The match is read
again every time EDSMT starts, so a HUD you recolour tomorrow is matched
tomorrow.

## The map

A top-down plan view with **you in the middle**, north up. Deposits are pins
with their range in metres and their commodity. Anything beyond the edge gets
an arrowhead pointing its way, with the distance. Scroll to zoom. Click a pin
and it tells you how far, which way, and whether to go left or right from
your current heading.

**It is the signal you are at.** Drive into a signal you have logged and
EDSMT picks it for you, once — a number you then pick by hand stays picked
until you drive into another. The map and the scope are sized to that signal:
its finds, its border and its rigs. If the Signal box still names a signal
somewhere else on the body, the views show the ground round the SRV instead,
and say where that signal is.

**The planning circle.** Right-click the map for **Planning circle here
(4.5 km)**: a ring of 4.5 km round the spot you clicked. Put your rigs down
and drive inside it and none of them is ever far enough behind for the game
to take it (it does at 5 km). The ring stays where you put it as you drive,
shows on the map and the scope, and the map's footer and the scope say how
much room is left to its edge - or how far outside it you are. **Clear the
planning circle (not a rig)** is on the same menu only while there is one;
it takes the green circle away and nothing else.

**What every mark is.** The **?** in the map's top right corner opens the
map's key; so do **Map key** on the right-click menu and **Help → Map key -
how to customise the map**, and the welcome has the same page. In short:

- The **white arrow** in the middle is you. Its colour is in Settings →
  Theme; its size (Standard, Larger, Largest) is in Settings → Overlay → Map
  and scope.
- The **line with a dot** beside you points at the next waypoint, the ship or
  the parked Rhino. It is not you.
- The **small circles** are the guided survey's waypoints: where to press
  your mineral scanner if you don't hold it down all the time. The ringed
  one, **WP n**, is next; grey ones are done.
- **LANDED** is waypoint 1: where you touched down. Your ship may have left
  since. EDSMT says so once, in words and by voice.
- The **solid amber ring** is your survey border and the amber cross its
  centre; the **dashed cyan circles** are the ones to drive; the **faint
  dotted rings** are range rings round you; a red **GAP** is ground inside
  the border not swept yet.
- A **numbered square** is a rig. The **red and green bands** round it are
  the spacing rings. The **dashed green 4.5 km circle** is the planning
  circle.

**A switch for each layer.** Right-click the map: under the key there is a
tick for the survey border, the circles to drive, the range rings, the
guided-survey points, the gaps, the pointer and the lines between deposits.
The same switches are in the key's window and in Settings → Overlay → Map
and scope. They apply to the map and the scope, and are kept. Hiding the
guided-survey points does not stop the guided survey: its line of words
stays.

**Right-click what you want to change.** On or near a waypoint: **Waypoint
n: remove it** takes it off the survey (the rest are numbered on from 1),
and **skip it** leaves out the one you are driving to. LANDED can be removed
the same way. On or near a rig: **Rig n: pick it up** and **Rig n: change
commodity**. **Recentre** and the planning circle follow.

**Lines between deposits.** Switched on (it starts off) and zoomed in - a
view of 1.5 km or less, or closer than the map opened at - a thin dashed
line joins each deposit to the one nearest it, with its length. On the scope
they show at 2x and 4x.

**Other commanders' finds are on it too.** Arrive on a body and EDSMT asks
the community map for everything already shared there. Those finds are drawn
as diamonds — on the map, the scope and the mineral deposit card — so you
can tell at a glance what is yours and what somebody else logged. Click one
and it says who shared it and when. A shared find sitting on top of one of
your own is shown once, as yours.

## Surveying an area

So you know you have covered the whole of a mining area, not just the bits
you happened to drive through.

1. Drive to the middle of the area and press **Alt+1** — logging the signal
   sets the centre.
2. Hold the mineral scanner down and keep holding it. Drive out to the
   location's edge line and press **Alt+2** (BORDER) there. That sets the
   radius. Pressed at the edge first, before the centre, the point is kept
   and becomes the border as soon as the centre is set. The scope keeps you
   in the picture out to 8 km, and the guide says how far from the centre
   you are.
3. Drive the circles drawn on the map. Everywhere your scanner has swept is
   shaded; what is left is not.

The Survey area panel and the STATUS box say how much is swept — **AREA
SWEPT 83%**. It only reads 100% when all of it is, never rounded up. Each
circle is spaced so that the scanner's 2 km passes overlap a little, so
"drive the circles" leaves no gaps. The map is kept per body and
saved as you go, so you can come back tomorrow and carry on where you
stopped. **CLEAR** starts the area again, and **MOVE CENTRE HERE** moves the
centre without logging the signal again.

## Rigs down

Press the rig's own key as you drop it — **Alt+4** for rig 1 up to **Alt+9**
for rig 6 — and the same number with **AltGr** as you pick it up. **RIG
DOWN** in the window, or a spare key you bind in Settings, puts down the
next free one instead. A rig already down somewhere else under that number
moves to where you are, and a double press on the same spot is not counted
twice. Settings → Rigs can also count a rig when you **hold the SRV's fire
button** — Primary or Secondary fire, whichever you pick — for a moment.
EDSMT reads what that is bound to from the game's own controls, so a mouse
button, key or HOTAS button all work, and a change in the game's Controls
takes effect without a restart. Each rig is a numbered square on the map, the scope and
the compass tape, in the colour of the deposit it is on, with that deposit's
commodity beside it. The STATUS box shows how many are down and how far the
farthest one is.

**How full each rig is.** Each tonne refined of a rig's commodity, after it
went down, is counted against that rig, out of the 12 a rig holds: the rigs
note shows each one's count (8/12), and **RIG 3 FULL** flashes at 12. It is
counted from the journal, so it is exact while each rig is on its own
commodity; with more than one rig on a commodity each tonne goes to the
nearest, and the counts show as estimates (~8/12).

Drive further than your limit from any rig (Settings → Rigs, 3,500 m unless
you change it — the game warns at 4 km and destroys a rig at 5 km) and every
overlay box you have open shows **TOO FAR FROM RIG**
and its number in red, with a warning sound if you want one. It
sounds once per trip out, not every second you are over the line, and is
ready again once you are back well inside it. Picking each one up forgets
it, **AltGr+0** (every rig up) forgets the lot, and leaving the body does too.
0 turns the warning off.

**The last warning.** At 4.8 km from a rig a big warning triangle takes the
middle of the screen and the warning sounds again — whatever the first
warning is set to, because 200 m later the rig is gone. Past 5 km in the
Rhino it is gone: EDSMT drops it, says so, and clears every warning for it.
**AltGr+0** clears the lot by hand at any time.

**A rig is marked where it lands**, 7 m behind the cockpit, not where you
are sitting. Settings → Rigs has the figure if yours lands elsewhere; 0
marks it under you.

**Too close, and time to collect.** Inside the rig spacing of one of your
own rigs (78 m unless you change it) every box says **TOO CLOSE TO RIG**
and its number, so you know before you drop the next one — drop it there
anyway and EDSMT marks it and says so. Back within a few metres of a rig
that has been working for two minutes, the boxes say **COLLECT RIG** and
its number, in cyan.

**Rigs survive a restart.** They are written down as they change, so
closing EDSMT, or a crash, does not lose them. When a Rhino docks in the
ship its own rigs come off the scope — the other Rhino's stay — and
Settings → Rigs turns that off. More than 6 km from where you are, in
anything, the rigs are forgotten and every warning goes with them; out of
the Rhino no rig warning goes up at all.

**Double-click a rig's square on the map** to put right what it is mining,
or to pick that one up. A rig dropped on a find somebody else shared — or
on the one you picked — takes that find's commodity.

### The rig planner

Drive to the deposit's
edge, press **AltGr+2**, and drive round the edge back to where you pressed
it: the loop closes by itself, or press the key again to close it where you
are. EDSMT works out where up to six rigs fit inside what you drove, each at
least the spacing apart — **78 m** by default, the community's working
figure, which you can change — and puts a numbered pin on the scope for each
one, in driving order. The scope closes in on the pins while you are near
them, STATUS says which pin is next and how far, the compass tape points at
it, and each pin goes green as a rig goes down within half the spacing of
it. The plan and the edge you drove are saved with the deposit and come back
when you return, and each deposit remembers how many rigs fit on it.

**Skip this pin.** A boulder on the pin, or you would rather start at the far
end: **Rig planner: skip this pin** (Settings → Keys, unbound to begin with;
a joystick or HOTAS button can be bound to it too) points you at the next pin
instead, as does **!rr skip** typed in chat. The pin stays on the plan; skip
past the last one and it starts round again.

### Chat commands

With **Run commands I type in the game's chat** on (Settings → Keys), a
message that starts with **!rr** is read as a command. Local chat is public:
everyone near you reads what you type there, so use wing or squadron chat if
you would rather they did not. Only your own messages are ever read.

| Type | What it does |
|---|---|
| `!rr alexandrite h/m 4` | mark Alexandrite here: High amount, Medium density, 4 rigs |
| `!rr 135 1.2km alexandrite` | mark it 1.2 km away on a bearing of 135 |
| `!rr rig down 3`, `!rr rig up 3`, `!rr rigs up` | rig 3 down or up; every rig up |
| `!rr centre` | move the survey centre here |
| `!rr undo` | take back the last deposit marked |
| `!rr signal` | log the signal here, as the signal key does |
| `!rr border` | set the survey border here |
| `!rr zoom` | step the scope: 1x, 2x, 4x |
| `!rr plan` | the rig planner: start tracing the edge, or close the trace |
| `!rr skip` | the rig planner: skip this pin |

The last five are for a session with no global keys - Wayland, or a
controller with no spare button: everything a key does there can be typed.

### Spacing rings and NEXT RIG

With a rig down, every rig gets a ring of your rig spacing on the map and
the scope: red while you are too close to any of them, green once you are
clear of them all. **NEXT RIG: 39 m, bearing 168** points to the nearest spot
the next rig can legally go. Rigs can be counted by key, by a joystick or
HOTAS button (Settings → Keys), by a chat command, or - if you switch it on
in Settings → Rigs - by holding your fire button in the Rhino. **Hold for**
sets how long counts, from 1 to 5 seconds (2 unless you change it): set it to
the hold that places a rig for you in the game.

### Shared rig layouts

When your rigs come up, how they were laid out on that deposit goes on the
community map — where each one went down and what it was on, and the edge
you drove and the pins, if you used the rig planner. Drive onto a deposit
with no plan of your own and the best layout anyone has shared for it — the
most rigs, newest first — shows on the scope as **SHARED PIN** pins, with the
same guidance as your own planner pins. Settings → Rigs turns the pins off.
Your commander name goes with a layout.

### The wing link

Mining one body with friends, or crew off one ship with more than one Rhino?
Switch on **Settings → Wing link**, and everyone types the same
six-character code (**Make a new code** makes one up to read out). Each of
you sees the others' Rhinos and rigs on the scope in a colour of their own,
and dropping a rig closer than the rig spacing to a wingmate's says so. Your
commander name goes with it. Nothing is stored:
you drop out two minutes after your last update.

**In a wing in the game, no code is needed.** With **Link with my in-game
wing by itself** on (it starts on), EDSMT reads who is in your wing from the
game and links you with each wingmate who runs EDSMT and has you in their
wing too — never with a commander who does not. Leave the wing in the game
and the link ends. A typed code still works beside it.

**One shared survey.** The ground you have swept on the body, the finds you
have marked and your rig plan's pins go over the link. On the map and the
scope each wingmate's Rhino, rigs, swept ground and finds are in a colour of
their own; a find a wingmate marks is said as it comes in, with how far and
which way; and with a survey border set, **Swept** and the gaps count the
ground the wing has swept with yours.

**Pins split between the wing.** On a deposit with a rig plan, the pins are
divided between the wingmates working it, in turn by name — so with Bee and
Jameson on six pins, Bee takes P1-P3 and Jameson P4-P6. Yours look as they
always have and you are guided to your own; a wingmate's are dashed, in
their colour, with their initial (**P1B**). A rig a wingmate drops on a pin
ticks it off for everyone. With no plan of your own you follow the wing's —
the one with the most pins. **Split the rig plan's pins between the wing**
turns the split off.

**A wingmate's collected rigs stay in the game until you leave the planet.**
In a wing in the same instance, a rig a wingmate has picked up does not
disappear for you until you fly away from the body. EDSMT's wing layer is the
true picture: the rig stays on the map and the scope, dashed and marked
**collected**, until you leave the body.

## My sites — your data window

**My sites** in the title bar is the one window for everything you have
recorded: every system, body, location and deposit, not just the body you are
on. A key of its own brings it up over the game — pick one in **Settings →
Keys**, **My sites: bring the data window up** (a joystick button works too).

The line under the title counts it all: systems, locations, deposits, the rigs
still to be had and the tonnes mined.

**The places list** on the left starts with a row a system, with its counts.
Open a system (double-click, or **open**) and its bodies are listed under a
heading for their kind of ground. Open a body and its locations follow, each
one line — how many deposits and rigs, the best commodities, how many are
worked out — and how far it is from you: metres on the body you are on, light
years to another system when both stars are known. A body you have surveyed
lists its **surveyed areas** too, each with a **picture** button.

Pick a location and **its deposits** are listed below: the map's own top patch
first, then the next, then the rest with the most rigs first, and the worked-out
ones last, saying what they gave last time (`worked out (340t)`). The columns
are rigs, where each is from the location's centre, the tonnes mined, what is
thought to be left, amount, density and when it was marked.

**The deposit card** beside them has everything about the deposit picked: its
position, which way and how far it is from you, amount, density, the tonnes
this time and what is left, the price known, when it was marked and whether it
is worked out. Its buttons:

| Button | What it does |
|---|---|
| **Guide me there** | the map and the overlay point at it until you get there, on whatever body it is; the line at the top of the window says where to go first, and **Stop guiding** lets it go. A deposit with no position or body recorded says why it cannot be guided to |
| **Share** | copies its share line |
| **Deposit depleted** | the same as **DEPOSIT DEPLETED** in the main window, on this deposit |
| **Copy position** | copies its latitude and longitude |
| **Delete** | deletes it from your records, after asking |

The location's **map picture** is drawn beside the card, with its top patches
circled; **map picture** on any site saves one and opens it.

**Your own marks**: every logged location has an up and a down mark. Up sorts
it to the top of the list in green, down to the bottom in red; press the lit
one again to take it off. They are yours only, kept on this PC and never sent.

The **Commodity** filter is followed by the whole window — the list, the places,
the counts and the deposits. In the materials picker, **Worth mining only**
ticks the materials selling for 100,000 Cr/t or more at the prices known now.
**Import...** sits beside **Refresh**.

The list on the right is every site, one row each:

| Column | What it says |
|---|---|
| **What is there** | your finds still there, what the signal offers that you have not found yet, and what the game says is worked out |
| **Finds** | how many you marked, and how many of those are depleted |
| **Rigs** | the rigs still to be had, at deposits not marked Depleted |
| **Mined** | the tonnes refined there |
| **Last there** | when you last logged or marked something there |

Type in **Filter** to narrow it by system, body or commodity — commas between
words mean any of them, so `Ega, Col 285` is both. **Commodity** ticks as many
commodities as you like and keeps the sites carrying any of them. **system**
copies the system name — paste it into the galaxy map to plot a route back.
Where you are now is in green.

### The deposit you are on, and the one you are going to

In the SRV, drive onto a deposit you marked and EDSMT picks it — **DEPOSIT DEPLETED**,
**UPDATE** and **Copy to share** then act on it with one click. The four boxes
on the left (Commodity, Rigs, Amount, Density) are filled in with what is
recorded for it, so an **UPDATE** starts from there and changes only what you
change. Pick a deposit
on the map or in the list and the overlay **guides you to it**: the scope and
STATUS say **GO** with the turn and the range, and TARGETS lists it first,
until you arrive.

A deposit's details say what it has given: **its own commodity's tonnes**,
with by-products beside them (not added in). Press **DEPOSIT DEPLETED** when it is
empty and that figure is filed as what it **holds**; work it again after it
has grown back and the details say about how much is **left**. A worked-out
deposit says how long ago it was worked out. How fast deposits grow back is
being measured from commanders who go back and check; until enough have,
EDSMT does not guess.

### Sharing one find

Click a deposit and press **Copy to share**. It goes on the clipboard as one
line anyone can read:

```
EDSMT find | HR 7280 | HR 7280 A 3 | signal 5 | Haematite | rigs 4 | amount High | density ? | 10.00100, 20.00100
```

Paste it in Discord. Anyone running EDSMT copies it, pastes it into the box in
**Settings → Your finds** and presses **Import** (or Enter) — chat around it is
ignored, and a find they already have is not added twice. EDSMT never reads
the clipboard by itself: only what you paste into that box. A deposit's
details also say where it is from the middle of its signal, so a friend can
drive straight to it.

## Where to land

The **Where to land** button lists every landable body in the system you are
in, best first, and fills itself in as you scan — honk, resolve bodies in the
FSS, map one with the DSS, and it keeps up without a click.

**It remembers every system you have scanned**, not just this session's.
The first start reads all your older journals once, in the background — the
summary line says how far it has got — and every new scan is kept as it
happens, in `bodies.db` beside your finds. Arrive somewhere your own
journals have not fully described and EDSMT asks the public body database,
through the community server, for the rest; the summary says how many bodies
came from there. Your own journal always wins over the public database.

| Column | Where it comes from |
|---|---|
| **Est. value** | the known sites still intact at what they carry, plus each location nobody has shared yet at what a site on that kind of ground usually carries |
| **Why** | a few words: known sites intact, locations nobody has shared, not mapped yet, or nothing found — rest the mouse on it for the whole sentence, which Copy copies too |
| **Locations** | the DSS count. *not mapped* until you map it — zero is only zero once the DSS says so |
| **Best bets** | what sites on this kind of ground have carried, from everyone's shared finds once there are enough of them, from the commodity tables until then — the line under it says which |
| **Known sites** | what has already been shared on that body, intact and worked out |
| **Yours** | your own locations and finds there |
| **Swept** | how much of your survey area there you have covered |
| **Ground** | body class, volcanism and gravity |

The value is an estimate and says so. Click a heading to sort by it;
**Copy all** puts the list on the clipboard for Discord. **Carrying** narrows
it to the bodies that carry the commodities you tick — one or several — what
their ground is known or expected to carry, and what has been found on them.

## The overlay

Turn it on with the **Overlay** button, or in Settings. It is **six separate
boxes**, each its own window, each switched on or off on its own — any
combination at once. They show only while the game is in front, and each key
you press says what it did over the game for a few seconds — RIG 2 DOWN
RHODPLUMSITE, SIGNAL 5 LOGGED.

| Box | What it shows |
|---|---|
| **COMPASS** | the tape across the top: which way to turn for every deposit, its range and its rig count. Anything behind you pins to the near edge with a turn arrow rather than vanishing |
| **SCOPE** | the patch from above — deposits coloured by commodity, sized by rigs, the 2 km scanner ring round your SRV, the drive order numbered on the dots |
| **TARGETS** | the nearest finds in order, and a bar per commodity sized by what it is worth |
| **STATUS** | body, deposit count, rig total, what is next, the estimated value of the patch and how far driving the lot is — and during a Rhino session, the ship's hold against its capacity and the Rhino's |
| **MINERAL DEPOSIT** | one card: a labelled readout of the deposit you are nearest, telemetry for the whole signal, and a signal radar with range rings and a contact per find |
| **GUIDE** | the step you are on, the key for it and what comes next — moves on by itself as each step is done |

**Three more lines on STATUS.** **SRV fuel** in tonnes while you are in the
SRV, with LOW beside it when the game says the tank is low; **t/h**, the
tonnes an hour for the session under way, the same figure Earnings shows; and
**Merits**, what the game has paid this session, only while you are pledged to
a Power. In the box as it comes they share one short line at the bottom left
(FUEL 0.31 t  12.4 T/H  1,250 MERITS), where the location otherwise is; drag
the box taller and each has a row of its own under the estimate and the
route. Each has its own switch in Settings → In-game overlay.

**When the Rhino and the ship will be full.** In the Rhino, three more lines:
**Rhino full**, how long until the Rhino holds 72 t and what it holds now;
**Ship full**, how long until your ship's hold is full by its own cargo
capacity, counting what the Rhino is carrying to it (it needs the ship's hold
seen once, so board the ship after a fresh start); and **Rhino load**, how long
your last load took from its first tonne to 72 t, with the average of the
last five. The times come from the rate of the load under way, or of the
session before a load has enough tonnes to go on. A load you unload before it
is full is not timed. One switch for all three: Settings → In-game overlay,
"STATUS line: Rhino and ship full in".

**Text size, box by box.** Settings → In-game overlay has a text size for
each box, 80% to 200%, on its own — bigger words without a bigger scope.

The compass and the scope update continuously, so they turn with the
Rhino. On a body at or over the gravity set in Settings (2 g to start with) a
warning triangle takes the middle of the screen when you arrive, once, and
GUIDE and STATUS carry a red **HIGH GRAVITY** bar for as long as you are
there. At 4.8 km from a rig the same triangle comes up for the rig.

**The default layout** is the compass across the top, the scope and the guide
down the left edge, the targets on the right and the status along the bottom
— all clear of the middle of the screen.

Every word on the scope is placed where it touches nothing else. When a
patch is too crowded to name every find, the nearest are named and the rest
are counted — scroll the map in the main window for the full picture.

**What else the scope says.** A **scale bar** in its bottom right corner, a
round length drawn to the scope's own scale. The header keeps **CENTRE SITE
4.10km NE**: how far, and which way, your survey centre is from where you
are. With a border set it reads **SWEPT 83%  2.4 km2** - the share of the
area and the ground swept. The keys along its foot are the ones you have
bound - site, border, deposit and rig, and where there is room the zoom key
and the rig planner's (**Alt+- ZOOM  AltGr+2 PLAN**); **Write the keys along
the foot of the scope** in Settings → Overlay takes them off. The zoom step
(1x, 2x, 4x) is kept, so the scope opens on the step you left it on. The
map's layer switches (right-click the map) apply to the scope too, and at 2x
and 4x the lines between deposits are drawn when their switch is on.

### Putting them where you want them

Press **Unlock** in the title bar — or bind a key to it in Settings, so you can
do it without leaving the game. While unlocked, every box grows a bar you drag
it by, a corner you resize it by, and its own name so you know which is which.
Press **LOCK** and they go back to being scenery: clicks pass straight through
to the game.

**Positions are stored as a share of the screen, not as pixels.** A box you
put 80% of the way across a 4K monitor is 80% of the way across a 1080p one,
scaled to match — so the layout follows you between a desk and a laptop. A box
left on a monitor you have since unplugged comes back onto one you still have,
with enough of it showing to grab. If a drag goes wrong, **Reset box
positions** in Settings puts everything back.

### Fitting a box to the cockpit

The boxes are flat rectangles; a canopy frame and a helmet visor are not.
While unlocked, press **SHAPE** in a box's bar. Four handles appear on the
corners of what the box draws: drag one and that corner moves, so the box can
lean the way the canopy does. The **BEND** slider across the middle curves the
box up or down, for the curve of a visor. The window itself stays a rectangle
and is still moved by its bar; only what is drawn in it changes shape. Press
**SHAPE** again to put the handles away (the bottom-right one sits on the
resize grip). **Flat again** undoes it, and **Reset box positions** flattens
every box.

A shape is kept as a share of its box, so it follows the box when you move or
resize it and fits any screen. Words are placed where the shape puts them and
drawn smaller where it narrows, but never turned, so they stay readable at
speed. A box with no shape set is drawn exactly as before.

### Themes and borders

The themes on the Theme tab (see **Themes** above). They change the whole
palette, background included, and apply to the overlay the moment you Save.
You can still type any `#rrggbb` to override the instrument colour on top of a
theme.

**Draw a border** decides where the frame goes: round the cards only (the
default), round everything, or nothing at all. The scope gets none by default
and its dish is not filled in, so it stays out of the way of the view.

**Ship minimap** (on to begin with): in the ship, below 10 km over a body
with finds on the community map, the scope comes up by itself with the
body's sites round you, you drawn as a ship, and the range widened to suit
the height. It goes again as you climb away or land. In orbital cruise
nothing is drawn.

**Dark backdrop behind the boxes** puts a see-through dark panel behind the
overlay, for white and icy ground where the boxes are hard to read: Off,
Light, Medium, Strong or Solid. **Darker by itself on icy and rocky-ice
bodies** (on to start with) takes it to at least Medium on those bodies, from
the body type in your journal, and never lighter than you set it. Every other
body keeps the backdrop you picked.

It **cannot** draw over the game in exclusive fullscreen; that is a DirectX
limitation. Set Elite to **borderless** or windowed and it appears.

## Voice

Everything here is on **Settings → Audio**: the voice, the speaking rate,
what is said, the spoken directions, the sonar, the comm effects and the rig
warning's sound, with **Test voice** and **What did it say?** beside them.
It is off until you switch it on, and works on Windows only - it uses
Windows' own speech and tones. On the first start, and once after updating
to a version that has it, EDSMT asks **"Do you want EDSMT to speak?"** -
Yes, No or Choose a voice - before any voice is heard, and does not ask
again.

**Voice Mode** says what EDSMT just did: signal logged, border set, deposit
recorded, rig three down, all rigs recovered, update ready, backup complete,
the session starting, pausing and ending, a rig plan ready, on the pin,
half the survey area swept and all of it (once each for an area), a
high-gravity world, the wing link up, a wingmate joining or leaving, a chat
command not understood, and the rest. The words are the **Basic voice line pack**, in one of five
voices: **Celestia**, **Ship computer**, **Flight controller**, **Radio
Raxxla on-air** or **Windows voice**. Windows voice is Windows' own speech and
nothing else: plain words, no recordings. It works on any PC, and it sounds
flat and robotic beside the recorded voices; it is there for anyone who
wants it. **Speaking rate** sets how quickly they are read, and **Test
voice** says the test line in the voice and rate in the boxes, saved or not.

Celestia, the Ship computer, the Flight controller and Radio Raxxla on-air
come recorded: every Basic line in each, free with EDSMT.

**The voice you pick is the only one you hear.** A voice says only what it
has recorded and is never filled in by another: a line, a distance or a
question it has no recording of is not said. Windows voice is a voice like
the rest - it reads words, and only when it is the one picked.

Voice Mode also tells you, once for each thing it is about: a deposit worth
a lot (one of the five best-paying on the prices known, or the best of all)
when you mark it or drive onto it; a rich patch when you mark one in a top
patch of three or more deposits; a deposit nearly worked out, or with plenty
left, when you drive onto it; the best price for your cargo with the SELLING
HERE flash; the Rhino five minutes from full, your ship one load from full,
and the hold full (each once a load); one of yours within 2 km due a check;
Guide me there set to another body; touchdown marking waypoint one; Skip this
pin; an import finished; a new ribbon on the community map; and your Twitch
live status switched on or off.

**Celestia** - the Celestial Event Liaison & Tactical Information
Algorithm, Radio Raxxla's voice of the Void - is the main voice and the one
a new install uses. She talks to you over comms, and the comms sound
different in a small, medium or large ship, in the Rhino and on foot: EDSMT
picks the right one from where the game says you are and the ship you are
in, with nothing to set.

**Supporter voices.** Every voice speaks every line of the Basic pack for
everyone. Supporters, and Radio Raxxla staff, also get the rest of Celestia:
her Short and Chatty answers, her later takes, her reactions and asides, the
voice-pack reminders, and distances and directions in her own voice. Pair this
computer (Settings → Sharing → Radio Raxxla account) and EDSMT fetches them by
itself, at start and every few hours; Settings says whether supporter voices
are on. They come in one download (about 45 MB the first time), so the whole
voice arrives together, usually inside a minute; nothing else EDSMT does waits
for it, and the status bar says when they are here. Without them, Short and Chatty answer as Normal does, and she says no
distances.

**Answer length** (Celestia, with supporter voices): **Short** is a few words -
"Deposit logged." - **Normal** is her usual lines, and **Chatty** adds to
them: a different take of a line now and then, a word about what the
journal shows (the Rhino going out and coming home, a touchdown, a big sale,
mining locations found, heat, low fuel, a jump) and, when nothing has been
said or done for a while and nothing is dangerous, an aside about the
galaxy. None of it comes again inside a few minutes.

**Voice-pack reminders** (with supporter voices). If you drive the game by voice through a
VoiceAttack voice pack, Celestia reminds you of the phrase to say at the
moment the journal shows it is needed: **"Deploy the SRV"** after you land,
**"Dismiss the ship"** once the Rhino is out and the ship is still sat
there, **"Recall the ship"** when every rig is up, **"Transfer cargo"** with
a full Rhino by the ship, **"Board the ship"** when it is all done, and
**"Apply handbrake"** on a rig pin. Each waits a few seconds first and is
dropped if the journal shows it done in that time, and none is said again
inside ten minutes. The switch is on by itself when VoiceAttack has a voice
pack (a folder in VoiceAttack's Sounds folder); turn it on or off and it
stays as you set it. Your voice pack still does the work - EDSMT only
reminds you what to say.

**Where the recordings are.** Every line of the pack is a recording made for
EDSMT, shipped with it, for each of the four recorded voices. A recording is
a `.wav` named after the line,
in a `voice` folder beside EDSMT or in the data folder, under the voice it
belongs to - for example `voice\ship_computer\signal_logged.wav`, or for a
voice with comms, under the place as well:
`voice\celestia\srv\signal_logged.wav` (`ship_small`, `ship`, `ship_large`,
`srv` or `foot`). A
recording made for a place is played as it is; otherwise Celestia's own
recording is given that place's comm sound. The voices are `celestia`,
`ship_computer`, `flight_controller` and `on_air`. Spoken directions on a
clock face are read by the Windows voice (see below).

**More than one take.** A line may have several recordings: `signal_logged.wav`
and beside it `signal_logged_2.wav`, `signal_logged_3.wav` and so on are all
takes of the same line, in any voice. EDSMT plays one of them, never the one
it played last time for that line and not the last two when there are enough
to choose from. A line with one recording is played as it always was.
Supporters get seventy such takes of the lines Celestia says most, each
said another way; **What did it say?** shows the words of the take you
heard.

**Distances and directions, said properly.** A voice that has the recordings
says the distance and compass direction to the deposit the scope points at
in its own voice: "Nearest deposit, two point four kilometres north-east".
Every distance is one recording of the whole phrase - `dist_m_340` is "three
hundred and forty metres", `dist_km_2p4` "two point four kilometres",
`dist_km_12` "twelve kilometres" - followed by one of the sixteen compass
points (`north`, `north_north_east`, `north_east` and so on round to
`north_north_west`), so a number is never pieced together word by word.
Metres are said to the nearest ten, kilometres to a tenth, and from ten
kilometres to the whole kilometre. Celestia has all of them with supporter
voices. If a recording
the line needs is missing, or the distance is a hundred kilometres or more,
the line is not said: never part of it, and never in another voice. Settings → Audio says
how many lines and blocks the voice picked has recordings for.

**Comm effects** (Celestia and the Flight controller) is on to begin with:
their recordings are given the
comm sound of where you are. In the ship it goes by the ship's size: a small
ship's tight cockpit is narrower and a little boxy, a medium ship sounds as it
always has, and a large ship's bridge is wider with a little room in it. The
Rhino has its own short-range set and on foot the suit radio. Switch it off
and they are played clean.

**Output device.** Settings → Audio → **Output device** picks where the voice,
the recordings and the rig warning's sound play: the system's default, or
another output such as a headset. If the one you chose is not connected the
default is used until it is, and your choice is kept. **Refresh devices**
reads the list again. The proximity sonar's tones are played by Windows
itself and always use the default device. On a system that is not Windows
there is nothing to choose.

**Spoken directions** are for a headset, where the overlay cannot be seen.
In the Rhino, EDSMT says how far and which way to go on a clock face -
"Platinum, 340 metres, two o'clock" - to the rig plan's next pin, else the
guided survey's waypoint, else the deposit the scope points at, else the
nearest rig. It is said whenever that changes, and every so often while you
are driving (10 seconds to start with, 5 to 60 in Settings), never more than
one line every 3 seconds, and not over and over once you are on it. The
clock-face words are read by the Windows voice, so they are heard with
**Windows voice** picked. With a recorded voice picked, the deposit the scope
points at is said in that voice when it has the recordings - Celestia, with
supporter voices - and nothing else is said for it.

**Proximity sonar** is tones, no words. In the Rhino, a short tone repeats
faster and higher as the deposit the scope points at gets nearer: every 2
seconds at 1,500 m, five a second inside 25 m, nothing past 2 km.

The rig warning is already spoken by its own sound; Voice Mode says it only
when that sound is switched off, so the two never talk at once.

**What did it say?** Help → **What did it say?**, or the button beside Test
voice in Settings → Audio, lists the last fifty lines the voice spoke, newest
first, each with the time it was said.

### A VoiceAttack profile

**Settings → Keys → Make a VoiceAttack profile** writes
`Radio Raxxla EDSMT.vap` into the data folder and says where. Its commands -
"mark signal", "set border", "mark deposit", "rig one down" to "rig six
down", "rigs up", "update deposit", "next waypoint", "overlay" and "lock
overlay" - press the keys on the Keys page, so make it again after changing
one. A job with no key is left out, and EDSMT says which. In VoiceAttack,
**Import Profile** and pick the file. What is and is not confirmed about the
file is in [VOICEATTACK.md](VOICEATTACK.md).

## What a patch is worth

EDSMT prices a patch as rig count times what the commodity sells for, using
the community's live prices where they are available and the published table
where they are not. The estimate is on the SCOPE, on the STATUS box, and as a
bar per commodity on TARGETS.

**BEST PATCH and BEST VALUE are bracketed separately.** One is where the most
rigs are; the other is where the most money is. On a body with one commodity
they are the same bracket.

Anything nobody has priced yet is counted and said out loud — *"4.18M Cr, +3
unpriced"* — rather than quietly left out of the total.

### The drive route

The order to drive them in is numbered on the dots, nearest-next from where
you are standing, with the total distance on the STATUS box. It is not the
shortest possible route, but it is the order you would drive anyway, and having
it on the map saves working out which dot is closest.

Worked-out deposits come off the route and stay on the map. The route is what
to drive; the map is what is there.

## What a session was worth

EDSMT follows your Rhino sessions from the game and your own rig keys, and
keeps a history of each one in `sessions.csv` next to your finds, so it is
already inside the backup.

While you are playing, the telemetry strip shows the session in progress —
how long, how many tonnes mined, how many moved to the ship — and what the
hold is worth at the last market you saw. The **Earnings** button opens the
history: when, where, what was mined, what went to the ship, what sold,
credits, and credits per hour of mining.

How a session is counted:

- **Only the Rhino counts.** Tonnes refined by the ship, mining asteroids for
  example, are not booked.
- **Moving ore to the ship does not mine it twice.** Transfers are counted in
  their own column.
- **A sale is put against the session that dug it up,** newest first, and
  never more than it dug. A sale of anything no session dug up — trade
  goods, exploration data — is not booked at all.
- **The drive to the station is not mining time.** A finished session keeps
  the time it was mined in, so credits per hour means credits per hour of
  mining. In Multi-session the whole haul is the session, by design — and
  Pause takes the drive back out.

A session is saved as it goes, so a crash or power cut costs only the closing
mark. Runs written by builds before 1.10030 stay in the file but are not
shown.

## Importing from other tools

**My sites → Import...** reads a bookmark database, pasted share lines, a
survey CSV or a map JSON exported by another mining tool - the contents
decide which, whatever the file is called. It shows what is new, what you
already have and what it skipped, and why, before anything changes, and makes
a dated backup first.

Settings → **Import another tool's CSV** also reads a `surfaceminingmap.csv` in
either of the two layouts other surface-mining tools write. Both use the same
file name, so the header row decides which it is — you are never asked.

**Finding the file.** Opening the import window looks in the places such a
database is kept and, if it finds one, reads it for a preview. Nothing is
chosen by the file's name or folder: a file counts when its tables and columns
are what a bookmark database has. A backup is offered only when the live file
is not there. Any file you choose yourself is checked the same way.

**What comes in** from a bookmark database, beyond the position of each find:

- the tonnes: what is mined at a deposit this cycle, and each cycle worked out
  as a dated figure. Only cycles opened at High measure what a deposit holds,
  and the preview says how many those are. A cycle that was never marked
  worked out is kept as a note line, not as a figure;
- the dates: depleted, each look that found it still depleted, and each time
  the other tool took the depleted mark off (a note line, with the date it
  carried). The first date it was depleted is kept. "Last there" is the date
  in the record, never the day you imported;
- the last-edited date, as a note line;
- your good and bad marks on locations. They are kept on this PC only and are
  never shared. A mark you have already made yourself is left as it is;
- the centre, border and swept ground of each map, so a location opens on the
  map as it was surveyed. A centre you logged yourself is never moved, and a
  map already held for the same area is left alone.

**What is kept apart.** A bookmark with no location number is filed under "no
location recorded", never under signal 1, and is not sent to the community map.
A bookmark the other tool had itself taken from somebody else's shared line is
kept for you, marked "not yours", and never sent. Bookmarks with no rigs are
counted in the preview ("3 with no rigs") and come in without a rig count.

**Map pictures.** Tick "Copy its saved map pictures too" to copy them into your
pictures folder. It is off unless you tick it.

**New since last time.** After the first import, opening the window says how
many bookmarks were made in the other tool since ("12 new since your last
import"). They are only offered: nothing is imported until you press Import.

It never imports the same file twice — keyed on the contents, so a renamed
copy is caught too — never overwrites a find you already have, takes a backup
before the first row goes in, and refuses a file it does not recognise by
naming exactly what it expected to see.

## Sharing

Every deposit you mark goes on the community map, and everyone else's turns
up under **Find** and on your map. There is no switch for this: the map is
only useful if everybody's finds are on it.

What goes up is the system, body, commodity, position and how rich it was,
and the prices at markets you open, with your CMDR name. Your notes,
sessions and settings never leave your PC — sessions go to your own Discord
channels only if you set them up. When your rigs come up, how they were laid
out goes too (see *Shared rig layouts*).

Each copy of EDSMT asks the community map once for a key of its own and
sends it with everything it asks the map for. It is kept in a file of its
own in the data folder (`install.key`), never shown and never in your
settings, so a settings file you pass on never carries it.

### The leaderboard

The **Leaderboard** tab ranks the commanders who share finds: this
week (from the Powerplay tick, Thursday 07:00 UTC), this month, last month
and all time, in three views. **By points**: finds (more when a find has
rigs, amount and density), the first find on a body, finds staff confirm,
old sites seen again, worked-out reports, deposits found grown back and
shared rig layouts, plus more for finds far from Sol (+5 beyond 500 Ly, +10
beyond 2,000, +20 beyond 10,000, +30 beyond 25,000). **Powerplay overall**:
your Power, rank and total merits as the game reports them, read from the
journal. **Merits from mining**: what the game paid for selling what you
mined. Each view has its own Powers table. Everyone who shares is on it
until they press **Leave**; **Join** puts them back. The board shows twenty
commanders a page; **Previous** and **Next** turn the pages.

**Share my week** makes a card of your week on the surface — finds, sites,
bodies and systems, your best patch, your furthest find from Sol, your
place on the week's board, merits and the ribbons you earned — drawn by
the community map from what you shared, saved in the pictures folder and
opened, ready to post. The same card is on the weekly page under *Your
week*, and on your member page.

### Squadron share

**Settings → Sharing → Share my squadron stats with my squadron's site** is
off until you turn it on, and does nothing until the journal has named your
squadron (the game writes that when it starts with you in one). On, it
fills your squadron's site from the game with four things: your carrier's
location and scheduled jumps, its buy and sell orders, your Powerplay rank
and merits, and the tonnage you deliver to colonisation builds. Nothing
else is read — not credits, carrier finance, what a carrier cost, your FID
or anybody's chat. The text under the switch says exactly this.

### EDDN

**Settings → Sharing → Send mining locations to EDDN** is on to begin
with. When the FSS reports Planetary Mining Locations on a body, that
body's signal counts go to EDDN, the network other Elite tools read, with
your CMDR name as the uploader. Nothing else goes from EDSMT: not your
finds, not where you are on the body, not credits. Only what the game
reports as you play is sent — never an old journal read back — and only
when the system it names is the one the game last said you were in. Beta
versions of the game send to the network's test channel instead. The line
under the switch counts what went this session.

### Mining bodies galaxy-wide

**Find → Mining bodies** lists bodies near you that carry mining
locations, from what commanders' tools publish when they scan and map —
not only the ones somebody marked in EDSMT. Each row has how many
locations, whether it is DSS mapped, the kind of ground, how often a
commodity has turned up on that ground (with how many sites that rests
on), and how many sites are already on the community map there.

### A site as a picture

**card** on a site in Find's Sites and Still there tables, or on a body with
known sites in Where to land, makes a picture of it: the body's shared finds
where they are, the site in the middle and the rest of the body faint, with
one line under it saying what the map knows — finds, rigs, commodities and
who found it first. It is saved in the pictures folder and opened. If EDSMT
has not fetched that body's finds yet it asks the community map and draws
the card when they arrive.

### Mining for a Powerplay goal

**Find → Powerplay** lists where to mine and where to sell for a Powerplay
goal. Pick **My power** (*Auto* reads it from your journal), the **Goal**
— Reinforce, Acquire or Undermine — and, if you like, who it is contested
by, a commodity, the distance, pad, demand, price age and state. Each row
is one place to mine and one place to sell: the site, its system's Power
and state, the station with its pad, demand and price age, how far apart
they are, and an estimate an hour. Merits an hour read "-" until the
community map has measured enough to say. The line above the table says how
fresh the Powerplay state is.

The **Powerplay** tab has two pages of its own: **Where it counts**, the
systems where selling counts for your Power, and **Where to sell**. Each
table shows twenty rows a page, with **Previous** and **Next** under it and
a line such as *Page 2 of 7 - 132 systems*. A search runs without holding
the window: the page says *Searching* until the answer is in, and
everything else carries on working meanwhile.

### What the community has measured

Mark one of your worked-out deposits full again and the map learns how long
deposits take to come back; every depleted deposit then says what those
reports measured. Shared rig layouts also say how close two rigs have gone.

Find is one search at a time: the switch at the top chooses **Sites**,
**Still there**, **Deposits**, **Sell prices** or **Mining bodies**, only that
search's filters are on screen, and **Search** (or Enter in any box) runs it.
**Due a check**, the last on the switch, reads your own records and lists the
deposits nobody has confirmed for a while, nearest first, with other
commanders' finds on the bodies you have been to (see Keeping the map right,
below).
It opens on the search it was left on. Sites, Still there and Deposits are
filtered by commodity, minimum rigs, how many different commodities sit in
one patch, how recently anybody confirmed it and a system or body name, and
they list every match, not the first 500. Every row has a **Distance** column
— light years from where you are now, whether or not you picked a radius.
**Saved**, beside Reset, keeps a set of filters under a name, with the search
they belong to.

**Tick several commodities.** Every commodity box in a search — Find, Where
to land, My sites and System prices — opens a list of tick boxes. Click
one, click another, click a ticked one again to take it off; **Any** clears
them. Or type: `Monazite, Bast` and Enter ticks Bastnäsite beside it. The
search then finds anything carrying **any** of the ticked commodities.

Age is part of the ranking. Ring hotspots are permanent; surface deposits are
not, and Frontier have said they "regenerate at a very slow rate", so a site
nobody has touched in three months sinks below a smaller one confirmed last
week.

### Keeping the map right

The map is only as good as the last person to check it. When you drive the
SRV onto a deposit you have marked, EDSMT asks once, on the overlay, and
aloud with Windows voice picked: Still there? UPDATE or DEPOSIT DEPLETED. UPDATE puts the Amount,
Density or rigs you can see now onto it. DEPOSIT DEPLETED marks it worked
out and sends the tonnes it gave, so everyone can see what a deposit like it
holds.

Other commanders' finds too. Drive onto another commander's find with none
of yours under you and EDSMT asks the same, saying whose it is. UPDATE says
it is still there and DEPOSIT DEPLETED that it is worked out; either goes on
the community map for everyone. It is not asked about a find somebody
reported today, nor one already worked out.

Drive off without answering and EDSMT says so in one line and keeps the
deposit on a short list (your own deposits only). At the next start a small
window offers Still there, Deposit depleted or Skip for each one, and Show
opens the deposit in My sites so you can tell which one it is. It never
holds the start up, and it is not there when the list is empty.

Each row says which deposit it is, because two deposits of one commodity in
one location have the same name: its rigs, Amount and Density, where it lies
from the location's centre, how far it is from you when you are on its body,
and its position as the Rhino shows it. **Show** opens the deposit in **My
sites** with its card and its map, on any body, and picks it on the main map
when it is on the body you are on. It stays on the list.

A worked-out mark stays until you take it off, or until the first tonne is
refined there. Once enough commanders have reported how long deposits take
to come back, a worked-out deposit says when it is expected back, and after
that it reads "may be back - needs a check". Find has a Due a check search:
your deposits nobody has confirmed for a while, nearest first, and other
commanders' finds on the bodies you have been to, each saying whose it is.

Checks count on the leaderboard: 2 points for an update, 3 for mined out, 5
for finding a worked-out deposit grown back. The Site checker ribbons count
them too.

### Sell prices

**Find → Sell prices** answers *where does this actually sell*, nearest
first, with the distance in light years on every row — for every commodity
you ticked, in one table. It combines live market data with prices read at
markets in other commanders' games, and says which is which.
A station in a system nobody has placed reads "-" rather than sorting to the
top as the closest thing in the galaxy.

Every commodity market you open adds its surface-mining prices to the
community's.

### Your own Discord channels

Every find already appears in **#edsmt-finds** on the Radio Raxxla Discord,
posted by the community map — nothing to set up. **Join the Discord** in
Settings opens the invite.

**Settings → Sharing → Discord** adds channels of your own, up to five. **Add
a webhook**, give it a name, and paste a channel's webhook — the channel's
**Edit Channel → Integrations → Webhooks → Copy Webhook URL**. Each webhook
has its own switches: **Finds** posts every find you mark (commodity, rigs,
system, body, signal, amount, density, position); **Sessions** posts a
summary of every Rhino session when it ends — tonnes of each commodity,
time, t/hr, credits, Cr/hr and where you sold — and updates that same
message when the cargo is sold; **Session card** sends the session card with
it (see Streaming, below) and the summary shows it, and **Session map** sends
the map picture as well. A summary without the card shows the map. **Test**
posts one message to that webhook, saved or not; **Remove**
takes it off the list. If one channel refuses a post, the status line names
it and the others still get theirs. A webhook you had before 1.10040 is
kept as the first, named "My Discord", posting what it posted before.

Each address stays behind dots like a password and goes to Discord and
nowhere else — not into a support bundle or crash.log. Nothing in a post can
ping anyone: an `@everyone` typed into a note is just text. Your commander
name is on the posts, since they are your channels.

**Show your Rhino session on your Discord profile** (Settings → Discord, off
to start with) is Rich Presence: your profile says Playing Surface Mining
with EDSMT,
what you are mining, the Cr/hr and the rigs down, with how long the session
has run, and buttons to get EDSMT and join the Radio Raxxla Discord. It goes
through the Discord app on this PC, at most once every 15 seconds, and comes
off your profile when EDSMT closes or the switch goes off. In streamer mode
the body and system are left off it.

### Streamer mode

**Settings → Sharing → Streamer mode**, for when you are live. While it is
on, a **STREAMER** badge sits in the top bar, and the names of the system
and body you are in — on the overlay, the map's title, the status line and
the readouts at the top — read "a system 290 Ly from Sol" and "a body" until
you have been in that system for the **Delay** (0, 5, 10, 15 or 30 minutes;
15 to start with). Then the real names show. Your own Discord posts wait the
same delay; they are held in memory only, so closing EDSMT drops them, and
the next start says so. Your finds still go to the community map at once.
**Bigger text** makes the overlay's text two sizes larger while streamer
mode is on. Find, Earnings and the other tools are not hidden, and nor are
station names. Turn streamer mode off and the names are back, and anything
held is sent.

**Your live status for the Radio Raxxla Twitch bot.** Settings → Sharing → **Show my live status to
the Radio Raxxla Twitch bot**, off unless you switch it on. While it is on, about every half minute
EDSMT tells the community map your system and body (never a position, and not while streamer mode is
hiding them), your ship, your ranks and how the session is going, and the bot can answer `!system`,
`!ship`, `!rank`, `!session` and `!edsmt` in your Twitch chat. Switch it off and it is taken down at
once; nothing of it is sent while it is off.

### Streaming

**Settings → Overlay → Streaming** puts your Rhino session on a stream
without a screen capture of EDSMT.

- **Serve an OBS browser source on this PC** (off to start with) serves two
  small pages on this PC only — 127.0.0.1, at the **Port** below it (8765
  unless another program needs that one). Nothing on your network or the
  internet can reach them, and they load nothing from anywhere else.
- **Copy overlay address** puts `http://127.0.0.1:8765/overlay` on the
  clipboard. In OBS, add a **Browser Source**, paste it as the URL and give
  it the size of your canvas (1920 × 1080). It shows, top left on a clear
  background in the app theme's colours: your CMDR name, the body and
  system, the session clock, tonnes by commodity, Cr/hr, merits when there
  are any, rigs down and the nearest deposit with its distance and bearing.
  A session that has ended stays on it for 30 minutes.
- **Copy viewer card address** copies `http://127.0.0.1:8765/viewer`: a card
  about 440 pixels wide for a corner of the stream, or to take a picture of
  for a Twitch panel — your CMDR name, what you are mining and where, the
  session's tonnes, Cr/hr and your last find. No Twitch account or key is
  needed.
- `http://127.0.0.1:8765/card.png` is the latest session card (below), for
  an Image or Browser Source.
- `http://127.0.0.1:8765/state.json` is what the pages show, as data, for
  other tools on your PC - a Stream Deck button, a dashboard. Every field
  and how its schema number works is in docs/LOCAL-DATA.md.
- **Streamer mode** applies to all of it: while it hides the names on
  screen, the pages read "a system N Ly from Sol" and "a body" too, and so
  does the session card they show. Nothing on them says where on a body you
  are, or anything about you but your CMDR name.
- **Text shadow for streaming** (off to start with) draws a dark outline
  behind every word on the overlay boxes, so they read over bright ground on
  a stream.

The **Streamer** layout (Settings → Overlay → Layout → Apply layout) puts the
boxes clear of a webcam and chat, and takes their text to at least 130% so
nothing on a 1080p capture is smaller than 10 pt. A size you have set bigger
is kept.

**The session card.** **Session card** on Earnings → This session, or
**card** on any row of Sessions, makes one picture of that session in the
style of the weekly card: CMDR, body, system and date along the top, four
tiles of tonnes, credits, Cr/hr and merits, then what was mined, the
session's map and the time mined with the rate and the sale, with the EDSMT
badge in a corner. Once anything is sold it shows the sale, not the
estimate. It is saved in the pictures folder as
`card_<system>_<body>_<date>.png`. On each of your Discord webhooks,
**Session card** (on to start with, and switched on once for webhooks saved
before 1.10042) sends it with the session summary, and the card is drawn
again with the sale when the summary is updated.

### Your Radio Raxxla account

**Settings → Sharing → Radio Raxxla account** pairs EDSMT with your member
page. Sign in at radioraxxla.com with Discord — any commander can, in the
squadron or not — open **Tools**, press **Make a pairing code**, and type the

## Where your finds live

Everything EDSMT records is in one folder, and nothing else touches it:

`%LOCALAPPDATA%\RadioRaxxla\EDSMT`

    deposits.csv               your finds
    locations.csv              the mining location signals you have logged
    sessions.csv               what each Rhino session mined and earned
    imported.json              which files you have already imported
    settings.json              written by the Settings window
    settings.json.bak          the last good copy, kept automatically
    settings-history\          dated copies of your settings, the last thirty
    rigs.json                  the rigs you have down, so a restart keeps them
    bodies.db                  every body your journals have described
    coverage\                  the survey areas you have swept, per body
    updates\                   a downloaded update, until it is installed
    journal-mining-events.log  diagnostic capture; attach it to a bug report if asked
    crash.log                  only if something goes wrong

**Settings are written safely.** The last good copy is kept as
`settings.json.bak`. A settings file that cannot be read is set aside and the
backup used, never overwritten with defaults, and EDSMT tells you on the status
line when that has happened.

**Earlier settings can be put back.** Whenever something that matters
changes — overlay placement, layout, theme, keys — EDSMT keeps a dated copy,
at most one every fifteen minutes, the last thirty. Settings → Your data →
*Earlier settings*: pick one and press **Put these back**, and the lot comes
back at once.

Plain CSV on purpose — open them in a spreadsheet, back them up, or take them
with you. **Updating EDSMT never touches this folder.** Settings → Your data
has **Back up now**, **Restore from a backup** and **Open my data folder**.
A backup carries your finds, signals, sessions, settings and their dated
copies, and the ground you have swept on every body; restoring one puts its
settings back straight away.

**A backup at every start.** Each time EDSMT starts, it writes one dated zip
of your settings, finds, sessions and survey to `C:\EDTools\Backup\RadioRaxxla\EDSMT`
(on Linux, `~/EDTools/Backup/RadioRaxxla/EDSMT`) and keeps the newest thirty.
It runs after the window is up, so it never slows the start. Keys and tokens
are left out of the zip. Settings → Your data says where it is and has an
**Open backup folder** button. The same page shows how many map pictures are
saved and how much room they take.

**Settings to a file and back.** Settings → Your data →
**Save settings to a file** writes your settings to a file you pick, with no
keys or tokens in it, for another PC or to keep. **Load settings from a file**
reads one back:
settings EDSMT does not know are ignored, a value of the wrong kind is
ignored, and your own keys and tokens are left as they are. The settings you
had are kept beside the new ones.

**Running it off a USB stick?** Put an empty file called `portable.txt` next
to `EDSMT.exe` and it keeps everything in a `data` folder beside itself
instead, so the stick carries your finds with it. Copy your existing files
across first if you have any — it does not move them for you.

### Going back to the previous version

On the single-file (portable) build, an update keeps the program file it
replaced, one copy, beside the new one as `EDSMT.exe.previous`. While it is
there, **Help → Go back to the previous version** appears; it asks first, then
puts that file back and starts it. Your finds and settings are not touched.
The installed build does not keep one: Setup replaces a whole folder, so go
back by running the older Setup from the downloads page.

## Linux

EDSMT runs on Linux from the same code, for Elite Dangerous played through
Proton (Steam), Lutris, Heroic or Bottles. Two ways to get it:

- **The one-file build.** Each release carries `EDSMT-linux-x86_64.tar.gz`
  on the GitHub Releases page. Unpack it, make the file executable if your
  archive tool has not, and run `./EDSMT`. It needs nothing installed.
- **From source.** Clone the repository and run `bash RUN.sh`. It wants
  Python 3.10 or newer with tkinter (`python3-tk` on Debian and Ubuntu,
  `python3-tkinter` on Fedora, `tk` on Arch), makes a `.venv`, installs what
  `requirements.txt` lists and starts EDSMT. Run it from a terminal the
  first time so you can read anything it says.

**Your finds live** in `$XDG_DATA_HOME/RadioRaxxla/EDSMT`, which is
`~/.local/share/RadioRaxxla/EDSMT` on nearly every desktop, with the same
files as on Windows. `portable.txt` works the same way.

**The game folder is found for you.** Elite's Saved Games folder sits inside
the game's Wine prefix, and every launcher keeps that somewhere different.
EDSMT looks in all of them — Steam's `steamapps/compatdata/359320/pfx`
(including Flatpak Steam and libraries on other drives), Lutris and Heroic
under `~/Games`, Bottles, a plain `~/.wine`, and whatever `STEAM_COMPAT_DATA_PATH`
or `WINEPREFIX` names — and where more than one has the folder, the one with
the newest journal is the one you are playing in. Anywhere else, set
Settings → Your data → Saved Games folder to the
`drive_c/users/<user>/Saved Games/Frontier Developments/Elite Dangerous`
folder inside your prefix.

**What is different on Linux**, and said again in Settings beside the
switch it touches:

- *The overlay* is the same boxes, dragged, locked and themed the same way,
  with opacity where the desktop is composited. Two things the X window
  system does not offer Tk: the dark background cannot be keyed out, so each
  box is a dark panel; and a locked box cannot be clicked through, so a
  click that lands on it stays with it. Lock the boxes and keep them clear
  of where you click in the game.
- *Hotkeys* are grabbed on the X server, which `RUN.sh` arranges by
  installing `python-xlib`; the one-file build has it aboard. They work with
  the game in front, as on Windows, and Settings → Keys says whether each
  took. On a Wayland session they are off, and Settings says so: use
  joystick buttons or chat commands there, or log in to an X11 session.
- *Joystick and HOTAS buttons* come from the kernel's own joystick
  interface, `/dev/input/js*` — nothing to install, no root. Plug the stick
  in before you bind a button to it.
- *The long press of the fire button* is not read on Linux; the rig keys,
  joystick buttons and chat commands do the same job.
- *Updates*: EDSMT still tells you when a new version is out, and the
  button opens the download page. The Linux file is on the release page
  beside the Windows ones; it is not installed for you.

Run Elite in borderless or windowed mode for the overlay, as on Windows.

### Cloud gaming

EDSMT reads the journal the game writes on the machine it runs on, so it
works wherever that folder is reachable:

- A **Windows cloud PC** you log into (a remote desktop that is a whole
  Windows machine): install EDSMT on it as on any Windows PC.
- A **Linux desktop service** where you install the game yourself through
  Steam, Bottles, Heroic or Lutris: unpack the Linux build beside it and run
  it there.
- A **streaming service that only shows you the game's picture**: not
  possible. The journal stays on their machine and never reaches yours, so
  there is nothing for EDSMT to read.

## Something wrong?

**Include the version shown in the title bar** in any report.

If the app does something unexpected it writes `crash.log` next to your finds
in `%LOCALAPPDATA%\RadioRaxxla\EDSMT`. Attach it.

**Trace mode** (Settings → About, under the support bundle) is for when
support asks for it. While it is on and a Rhino session is open, EDSMT writes
a line each time the game changes Status.json or Cargo.json — when it
happened, the game's flags and the cargo counts, and nothing else: no
position, no credits, no names. The support bundle carries those lines.
Leave it off otherwise.

**A long journal at start-up.** EDSMT reads the journal you are playing into
from the top when it starts, so it can carry on the session you are in. A
long evening's journal is read a chunk at a time while the window carries
on, and the status line says how far it has got.

| What you see | What it usually is |
|---|---|
| The overlay does not appear over the game | Elite is in exclusive fullscreen. Set it to borderless or windowed |
| An overlay box is off-screen | Settings → **Reset box positions** |
| Find returns nothing at all | Check you are online. Nobody may have mapped that commodity yet |
| Find says the service is unreachable | It will say why. Usually the service is down or the network is blocking it |
| System and body do not fill in | The app needs the game's journal folder. Settings → Journal folder |
| **NO ACCESS** in red at the top | Windows is refusing to let EDSMT read the journal folder — usually a hidden or protected Saved Games folder, or security software. Allow EDSMT, or point Settings → Journal folder at a copy it can read |
| "EDSMT is already running" | Only one copy runs at a time, so two cannot fight over your finds. Look on the taskbar |
| An update did not download | It says why on the status line. A download that does not match its checksum is thrown away and tried again later; Settings → **Check for updates** tries now |
| SmartScreen blocks the installer | Expected — the build is not code signed. **More info → Run anyway.** See SECURITY.md |
